webfs help

← Back to notes

webfs is a file explorer and markdown editor that runs entirely in your browser. Your files live on this device (in the browser's private file storage), and can optionally be synced to a GitHub repository. There is no server and no account.

Files and folders

  • + File and + Folder at the top of the sidebar create at the top level. In a narrow sidebar they fold into a single ＋.
  • Right-click a row (or long-press it on a touch screen) for its menu: New File, New Folder, Import Files…, Open, Open to the Side, Rename, Move to…, Delete. Right-click the empty space below the tree for the same actions at the top level.
  • Rename: double-click a name, or use Rename in the menu.
  • Move: drag a row onto a folder (or onto the empty area for the top level), or use Move to…, which lists every folder.
  • Import files from your device with the import icon in the sidebar header, with Import Files… in any menu, or by dropping files onto the tree from your desktop. Dropping onto a file puts them in that file's folder.
  • Folders open and close with their chevron. A drive you've just connected starts folded up.
  • Drag the sidebar's right edge to resize it; double-click the edge to reset.
  • Changes save automatically about half a second after you stop typing.
  • Names can contain spaces, accents and emoji. Two things in one folder can't share a name, so a new one becomes notes 2.md.

Searching and sorting

  • 🔍 filters the tree by name. A folder whose name matches shows everything inside it. Esc closes the search and brings back your folded tree as it was.
  • ⇅ chooses the order: Name (A–Z / Z–A), Modified (newest / oldest first), Created (newest / oldest first). Folders always come first, by name.
  • "Created" means when a file first appeared on this device. Files that were already here before that was recorded have no date and sort last.

Tabs and split view

  • Opening a file adds a tab. × on a tab closes it.
  • ▥ splits the editor into two panes; the new one starts empty — click a file to fill it, or use Open to the Side. ✕ closes the second pane.
  • A file is only ever open in one pane; opening it again jumps to where it is.
  • The address bar follows the file you're looking at, so you can bookmark or share a link to a note.
  • Open tabs, folded folders and the sort order are remembered per drive across reloads.
  • Several browser tabs can have webfs open at once; edits made in one appear in the others.

Writing markdown

The editor is WYSIWYG: type markdown and it's formatted as you go. The file on disk stays plain markdown, readable by GitHub, Obsidian or any text editor. Selecting text shows a formatting toolbar.

# Heading 1
## Heading 2
### Heading 3

**bold**, *italic*, ~~strikethrough~~, `inline code`

[a link](https://example.com)

- a bullet list
  - nested (Tab / Shift-Tab to indent and outdent)
1. a numbered list

> a block quote

---

```js
console.log("a code block, with syntax highlighting");
```

| Column | Another |
| ------ | ------- |
| cell   | cell    |

Only the lines you actually edit are rewritten. Opening or reading a note never changes it, and a note written elsewhere keeps its own style (tabs, * bullets, and so on) on every line you haven't touched.

The slash menu

Type / at the start of an empty line for a menu of blocks to insert: headings, lists, quotes, code, tables, images, maths, dividers — and webfs's own Todo list (see below). Keep typing to filter it, e.g. /tab or /todo.

Maths

LaTeX, drawn with KaTeX. Single dollars are inline, double dollars are a block — the same as GitHub and Obsidian.

Euler's identity is $e^{i\pi} + 1 = 0$.

$$
\int_0^\infty e^{-x^2}\,dx = \frac{\sqrt{\pi}}{2}
$$

Known issue: two prices on one line ($5 and $4) are read as a formula. The file is untouched; only the display is wrong.

Checkboxes

- [ ] buy milk
- [x] call the bank
- [ ] write report
  - [ ] outline
  - [x] gather numbers
  • Click a box to tick it. Ticked items are struck through and dimmed.
  • Every checkbox list gets a ⇅ just above it, which moves finished items to the bottom, keeping your order otherwise. Sub-items move with their parent. On a list that's already in order it does nothing at all.

The todo block

A fenced code block named todo shows every unfinished checkbox from all the notes in the drive:

```todo
```

Name a folder after todo to list only the notes inside it:

```todo Projects/Garden
```
  • Insert one from the slash menu with /todo.
  • Tick a row's checkbox to tick that item in the note it came from. Click the rest of the row to open the note.
  • ↻ refreshes the list. It updates by itself when the note it's written in changes.
  • Reads .md, .markdown, .mdown and .txt files, skips checkboxes inside code blocks and empty ones, and shows at most 200 rows.
  • In GitHub or Obsidian it's just an empty code block — the note stays ordinary markdown.

Images

  • Paste an image (or use the slash menu's Image block to upload one) and it's saved as a real file in an assets/ folder next to the note, linked relatively: 
    ![](assets/screenshot.png)
    That same link works when the note is viewed on GitHub.
  • Links to images on the web work as usual: ![alt](https://example.com/cat.jpg)
  • Opening an image from the sidebar shows a preview rather than the editor.

Obsidian embeds and links

Notes from an Obsidian vault open safely, and their embedded images are shown:

![[Pasted image 20260905101712.png]]
![[diagram.png|400]]
[[Another note]]
  • An image embed is looked for next to the note first, then in a Media/ folder at the top of the drive (Obsidian's usual attachment folder).
  • Embeds and links that aren't images are kept exactly as written and shown as text. A broken embed shows its own source so you can see which one it is.

PDFs and other files

  • A PDF opens in the browser's built-in viewer, with a link to open it in a new tab — on iPhone and iPad use that link, since Safari can't show a PDF inside the page properly.
  • Other files that aren't text are shown, never opened for editing, so they can't be damaged.
  • SVG images are text and can be edited.

Plain-text view

</> at the top right of a pane shows the note's raw markdown in a plain text box; ¶ goes back to the formatted editor. The choice is remembered per file.

Drives

A drive is a top-level folder of notes. The switcher at the bottom of the sidebar shows the current drive; click it to switch, or add one.

  • Local drive — a folder kept only in this browser.
  • GitHub drive — a branch of a GitHub repository, kept on this device and synced both ways.
  • The first visit creates a local drive with a few starter notes. Drives you add start empty.
  • The URL names the drive: …/opfs/notes/Notes/todo.md is Notes/todo.md in the local drive notes; …/owner/repo/README.md is in a GitHub drive.
  • Removing a drive forgets it; it doesn't delete its files.
  • There's no copying between drives yet: a new GitHub drive fills from the repository.

GitHub sync

  1. Add a drive, choose GitHub, and enter owner/repo and a branch.
  2. Create a fine-grained personal access token with the link in the dialog (it's pre-filled — pick the repository on GitHub's page), and paste it in.
  3. Sync runs when the drive opens, a few seconds after you stop typing, every minute, and when you come back online. Untick auto-sync to only sync with the button.
  • The strip at the bottom shows progress and when it last synced. main ↗ opens the branch on GitHub.
  • Edits on both sides to different parts of a file are merged. If both sides changed the same lines, this device's version wins.
  • Nothing is lost on a conflict: a file deleted on one side but edited on the other comes back, and two unrelated files with the same name are both kept, the GitHub one as notes (github).md.
  • Each sync is one commit, titled with the time and the file that changed.
  • Empty folders don't sync (git can't store them).
  • The token is stored in this browser only, never in the repository.

Sharing a drive

In a GitHub drive's settings, Share… shows a QR code and link. Opening it on another device asks before adding the drive there.

The link contains your token. Anyone who sees it, or photographs the QR code, can write to the repository until you revoke the token on GitHub.

On a phone

  • ☰ opens the file list as a drawer.
  • Long-press a file or folder for its menu (rename, move, delete…).
  • While the cursor is in a list, a pair of buttons floats above the line to indent and outdent it — the on-screen keyboard has no Tab key.
  • Only one pane is shown at a time.

Offline and installing

  • After one visit online, webfs works offline — all your files are on the device. A GitHub drive says when it's offline and when it last synced, and catches up when you reconnect.
  • Add it to your home screen (Share → Add to Home Screen on iOS, Install on desktop/Android) to use it like an app.
  • The small number in the top right is the build number, useful for checking you're on the latest version.

Keyboard

  • Tab / Shift+Tab — indent / outdent a list item.
  • / — open the slash menu on an empty line.
  • Esc — close the search box or a menu.
  • ← / → on the focused sidebar edge — resize the sidebar.
  • The usual Ctrl/⌘ + B, I, Z for bold, italic and undo.

When something goes wrong

  • If the app fails to start, it shows a report you can copy into a bug report, and a Clear cache and reload button. That clears only the cached app — your files and settings stay.
  • If a newer version doesn't seem to arrive, reload once more while online; the build number in the corner tells you which one you have.
